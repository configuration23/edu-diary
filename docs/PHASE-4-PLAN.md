## Шаг 4. Аналитика

**Переработка по решению владельца: раздел называется «Оценки и посещение».**

Что меняется против первой версии экрана:

- **выбор дат убран**: диапазон всегда **текущий учебный период** из «Учебного года». Если периода
  нет — сообщение «Период не задан»;
- **два переключаемых раздела**: «Оценки» и «Посещение»;
- **ученик и представитель** (дизайн одинаковый): по предметам — полный список отметок, в конце
  визуально отделённая средняя. Для посещения — полный список отметок и в конце процент пропусков;
- **отметки компактные, как в журнале урока**, без правки у всех ролей (правка только в журнале);
  в подсказку добавлена **дата** отметки;
- **знаки «+» и «·»** показываются в общем ряду (ученику видно, сколько до превращения в оценку), но
  **в статистику не входят**;
- **галочки «Считать уважительные как пропуски» и «Считать больничные как пропуски»** — переключатели
  на экране, при загрузке сброшены, ничего не сохраняют. Расчёт: по умолчанию пропуск — только `Н`;
  первая галочка добавляет `У`, вторая `Б`, обе — `Н + У + Б`. «Опоздал» (`О`) пропуском не считается
  никогда. Знаменатель — прошедшие занятия по предмету, у которых есть отметка;
- **преподаватель**: не по предметам, а **по ученикам** — у каждого ученика строка отметок по предмету
  преподавателя и итоговая, то же для посещения. Сверху выбор группы и предмета: один предмет —
  заблокирован, несколько — из назначений. **Уроки с заменой не учитываются**: внеплановую замену
  смотрит основной преподаватель, плановая смена оформляется назначением;
- **администратор**: к текущей странице добавляется выбор **группы** и **ученика**; остальное без
  изменений;
- **`/lessons/:id`** для ученика не трогаем — статус «обсудить потом».

**Готово:** расчёт пропусков в домене (`absenceStats`, 5 тестов), данные по предметам и по ученикам
на сервере (три маршрута, тесты API), экран с двумя разделами и галочками, сквозная проверка
(администратор выбирает группу и ученика, видит среднюю и проверяет влияние галочки на процент).

**Не покрыто сквозным сценарием:** вид ученика и представителя на этом экране (проверен
API-тестами). Добавить, если владелец сочтёт важным.

### Первая версия экрана (до переработки)

### Что показываем

Отчёт по выбранной группе за учебный период: строка на ученика.

- **средний балл** с весами причин: у каждой оценки вес из справочника причин, средний считается
  как `Σ(оценка × вес) / Σ(вес)`. Знаки «+» и «·» в средний балл **не входят**: это не оценки;
- **количество оценок** — числовых, без знаков;
- **посещаемость**: процент «присутствовал» от всех отмеченных занятий и разбивка по статусам
  (был, не был, болел, опоздал, уважительная) для круговой диаграммы.

### Решения

1. **Диаграмма — круговая, по статусам посещаемости.** Нарисовать её без внешних библиотек:
   обращение к CDN запрещено (`SECURITY.md` §3.8), а тянуть библиотеку диаграмм ради одного
   круга незачем. Строим SVG: сектора считаются из процентов, которые уже отдаёт домен
   (`attendanceBreakdown`).
2. **Проценты считает домен, не интерфейс.** Проверено правилом: расчёты живут в
   `packages/domain/journal.ts` и покрыты тестами, а экран только показывает.
3. **Отчёт доступен по тем же правам, что журнал**: `grades:read` — ученику и представителю
   только свои строки, преподавателю и администратору — по группе.
4. **Период выбирается явно**: по умолчанию текущий учебный период, при желании — произвольные
   `from`/`to` (как в пересчёте знаков).

### Что правится в существующем коде

Эндпоинт `GET /api/journal/stats` есть с шага 0, но **не работает по группе**: он требует
`studentId` и отвечает `400`, если его нет. Отчёт по группе — основная задача шага, поэтому:

- при запросе по `studyGroupId` список учеников берём из группы (состав на дату, а не текущий);
- в ответ добавляем имя ученика: без него отчёт нечитаем;
- состав отчёта описываем контрактом (`journalStatsResponseSchema`), а не «как получится».

### Проверки

- **домен**: средний балл с весами, отсутствие оценок даёт `null`, знаки не влияют на средний
  балл, проценты посещаемости по статусам (тесты уже есть с шага 0 — дополняем при нужде);
- **API**: отчёт по группе возвращает строку на каждого ученика группы, ученик получает только
  свою строку, чужой ученик даёт `403`/`404`, пустой период не падает, доступ без прав — `403`;
- **сквозной**: администратор открывает отчёт и видит средний балл и проценты.

Вёрстку диаграммы отдельно не проверяем (правило объёма тестов): если она окажется важной —
скажет владелец, тогда добавим проверку размеров и секторов.

### Чего не делаем

- **итоговые оценки за период** (табель) — отдельное решение после аналитики;
- **выгрузку отчёта** — шаг 5;
- **сравнение учеников между группами** — не просили.

## Решения владельца (по ходу этапа)

### Общие

1. **Посещаемость — отдельная таблица** `attendance_entry`, а не поле в `grade_entry`.
2. **Правило «плюсы/точки → оценка» — настройка порога**, счёт ведётся по предмету.
3. **Счётчик — внутри учебного периода** (ADR-009).
4. **Посещаемость в аналитике — круговая диаграмма** по статусам; процент «присутствовал» от
   всех отмеченных занятий.

### Уточнения после просмотра

5. **Буквы посещаемости:** `П` присутствовал, `Н` не был, `Б` болел, `О` опоздал.
   «Уважительная» — не пятая буква, а галочка к «Н»: в базе это признак `is_excused`.
6. **Причины отметок:** справочник «из коробки» (`Д`, `О`, `П`, `К`, `Э`, `С`, `Л`, `Т`, `З`,
   `Пр`), вес по умолчанию `1`.
7. **Справочник причин принадлежит заведению:** названия и веса правятся, свои причины
   добавляются (код до двух символов), занятую причину удалить нельзя. Синхронизация при старте
   добавляет недостающие, но не перезаписывает изменённые.
8. **Вес — целое от 1 до 5**, ограничение продублировано проверкой в базе.
9. **Несколько отметок за урок разрешены**; отметка с той же причиной отвечает конфликтом, а
   интерфейс спрашивает подтверждение замены.
10. **«Отметить всех присутствующими»** убрано из интерфейса, код и маршрут оставлены.
11. **Вид отметки в журнале — «5₁д»**: оценка, вес подстрочно (кроме веса `1`), код причины
    надстрочно; полное название — при наведении. Правка — нажатием на отметку, панель правки
    занимает строку во всю ширину таблицы. Отметки идут в строку, по пять в ряду.
12. **Посещаемость в журнале — только буква**, полное название в подсказке; «У» — та же неявка,
    но с уважительной причиной.
13. **Награда за знаки не настраивается**: плюсы дают `5`, точки дают `2`.
14. **Пересчёт съедает знаки:** ровно порог на одну оценку, оценка ставится датой последнего
    знака, лишние знаки остаются, состав съеденных знаков уходит в аудит. Повторное нажатие
    ничего не делает.
15. **Порог — общий для всех предметов.** Разные пороги по предметам не просили.
16. **Оценка за знаки выглядит как обычная оценка** (код причины из справочника, без отдельной
    пометки). Съеденные знаки в журнале не показываются, но остаются в базе.
17. **Удаление отметки посещаемости скрыто** в интерфейсе: поставив посещение, его пока можно
    только заменить другой буквой. Функционал и API целые и покрыты тестами, включается
    константой `ATTENDANCE_DELETE_ENABLED`.

## Что не делаем в этом этапе

- Домашние задания и вложения — Этап 5.
- Уведомления родителям — Этап 6.
- Итоговые оценки за период (табель) — обсуждается отдельно после аналитики.
