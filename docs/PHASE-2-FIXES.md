# PHASE-2-FIXES — правки по замечаниям к Этапу 2

План правок по замечаниям владельца (после сдачи Шагов 1–8 Этапа 2).

Источник: разбор интерфейса на тестовом стенде 10.10.2026. Замечания касаются
удобства и полноты уже сделанных разделов, новой схемы они не требуют —
кроме отложенных пунктов (специальность в справочник, гейт по редакции
политики).

Правило работы: один блок — один коммит с тестами. Этап 2 считается сданным
после закрытия блоков A–H и чистого прогона мастера на пустой базе.

## Вторая волна правок (после тестов на стенде)

Разбор владельцем 10.10.2026, после первой волны. Порядок — как договорились: сначала мелкие
недоделки и переезд учеников, крупное — отдельно.

### Партия 1. Мелкие недоделки

- [x] **Годы правятся**: `PATCH /api/academic-years/:id` уже был на сервере; добавлены хук, кнопка «Править» и форма (название и границы). Найдено по ходу: хук на клиенте существовал, но принимал только название — расширен на даты.
- [x] **«Примечание» в зачислении и отчислении**: поле добавлено в обе формы; при отчислении примечание перезаписывается только если его передали (основание зачисления не теряется). API отчисления расширен: `withdrawStudentRequestSchema.note` → сервис → репозиторий.
- [x] **Логин: результат у поля**. Подсказка («Логин свободен: …», «Базовый логин занят, предложен …») и текст ошибки показываются прямо под полем логина; общая плашка наверху страницы для этого больше не используется.
- [x] **Политика: текст и история**. Добавлен блок «Редакции политики»: все редакции с версией, датой, автором и раскрываемым текстом; действующая помечена. Пустое состояние — «Политика ещё не опубликована». Причина прежнего поведения: на экране выводился только `current.version`, сам текст и история не рендерились, хотя API отдавал их с самого начала.
- [x] **Назначения: подсказка про преподавателей**. Если преподавателей нет — предупреждение со ссылкой на «Пользователи и роли».
- Тесты: новый интеграционный тест на примечание (сохраняется при зачислении; при отчислении без примечания не теряется; при отчислении с примечанием заменяется). Итого 270 тестов.

### Партия 2. Ученики переезжают в «Группы и ученики»

Решение владельца: держать учеников в «Пользователях и ролях» было ошибкой — путает. Ученик —
основа группы, поэтому блоки идут первыми в «Группах и учениках».

- [x] Порядок в «Группах и учениках»: **«Новый ученик» + таблица «Ученики»** → «Новая группа» →
      «Группы» → состав группы.
- [x] «Пользователи и роли» сохраняет: «Новый пользователь», список пользователей, «Привязка
      законного представителя» и таблицу связей.
- [x] `StudentsCard.tsx` разделён: `StudentsCard` (ученики) живёт в «Группах и учениках»,
      `LinkGuardianForm` и `GuardianLinksCard` — в «Пользователях и ролях».
- [x] Права: блоки учеников показываются при `students:write@all` — преподаватель видит раздел, но
      без списка учеников (как и раньше). Признак передаётся из маршрута (`App.tsx`).
- [x] Смоук-тесты обновлены: проверяется и порядок блоков, и то, что преподавателю учеников не
      показывают. Итого 271 тест.

### Отложено осознанно (вернуться обязательно)

- [ ] **Группы и учебный год: правила дат.** Решение владельца — отложить, не критично для реального
      использования. Что нужно сделать, когда вернёмся: группа сейчас обязана помещаться в границы
      своего учебного года, а по жизни группа набирается в середине года и выпускается зимой, то есть
      живёт дольше года. Договорённый вариант — **смягчить правило**: группа не «внутри года», а
      пересекается с ним, и её начало/окончание совпадают с границей года или периода (тогда набор в
      середине года и выпуск в середине учебного года выражаются честно). Модель
      (`study_group.academic_year_id`, ARCHITECTURE.md §5) при этом не меняется. Отдельный вопрос на
      будущее — многолетние группы (цепочка записей по годам либо отвязка от года); его логично
      решать на Этапе 3 вместе с расписанием и уроками, отдельным ADR.
- [ ] **Специальности в справочник.** Владелец согласен, но признал не критичным: сейчас поле
      свободного текста в форме группы. Когда вернёмся: таблица `specialty` + миграция, API
      `GET/POST/PATCH/DELETE /api/specialties` с запретом удаления занятой, блок «Специальности» в
      справочниках, выбор из списка в форме группы; существующий текст у групп переносится как есть.
- [ ] **Счётчик «представителей» у ученика** — владелец заметил, что такой счётчик уже запланирован
      позже; отдельно не делаем.
- [ ] **Гейт по новой редакции политики** (см. Блок H) — ждёт решения по отказавшимся и исключениям.
