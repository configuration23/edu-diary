# PHASE-2-FIXES — правки по замечаниям к Этапу 2

План правок по замечаниям владельца (после сдачи Шагов 1–8 Этапа 2).

Источник: разбор интерфейса на тестовом стенде 10.10.2026. Замечания касаются
удобства и полноты уже сделанных разделов, новой схемы они не требуют —
кроме отложенных пунктов (специальность в справочник, гейт по редакции
политики).

Правило работы: один блок — один коммит с тестами. Этап 2 считается сданным
после закрытия блоков A–H и чистого прогона мастера на пустой базе.

## Блок A. Единый учёт учеников (корень проблемы)

Подтверждено владельцем: **ученик первичен, учётная запись — его атрибут**;
учётная запись создаётся **по необходимости** (не обязательна при заведении).

- [x] Контракты: `studentSummarySchema.username`, `studentAccountRequestSchema`, `account` в создании ученика, `suggestUsernameResponseSchema`.
- [x] Домен: транслитерация и подбор логина (`packages/domain/src/username.ts`, 11 тестов).
- [x] API: `POST /api/students` принимает `account` и создаёт карточку и учётную запись в одной транзакции.
- [x] API: `POST /api/students/:id/account` — учётная запись ученику, созданному ранее.
- [x] API: `GET /api/users/suggest-username?fullName=…` — свободный логин по ФИО.
- [x] API: `GET /api/students` отдаёт `username` (состояние связи видно в списке).
- [ ] Интерфейс: в «Пользователи и роли» блок «Новый ученик» (ФИО первым, дата рождения, примечание, чекбокс «создать учётную запись»).
- [ ] Интерфейс: там же таблица «Ученики» с состоянием учётной записи и действиями.
- [ ] Интерфейс: из «Согласий и политики» убрать создание ученика (остаётся ссылка на раздел).
- A4 (связывание осиротевших карточек) — **отложено**: чистого прода нет, сделаем при переразвёртывании с нуля.
- Замечание по ходу: вставка пользователя при дубле логина давала `500` — Drizzle оборачивает ошибку БД, а перевод ошибок стоял не на всех вставках. Теперь `409` с текстом «Логин уже занят» (проверено тестом).
