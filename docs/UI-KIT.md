# UI-KIT: классы объектов и правила

Короткий справочник: **что чем рисовать**. Нужен, чтобы новый экран не угадывал и не заводил
двадцатый вариант одного и того же. За соблюдением следит `npm run check:ui`.

Правило, из которого всё выведено: **одинаковый смысл — одинаковое оформление, разный смысл —
намеренно разное**.

## Токены темы

Цвет задаётся **ролью**, а не оттенком. Палитры (`slate-500`, `blue-700`) в экранах нет.

| Роль | Классы | Когда |
|---|---|---|
| Фон страницы | `bg-background` | обёртка страницы |
| Карточка, блок | `bg-card` | `Card`, `Section`, `Spoiler` |
| Вложенная панель | `bg-muted` | шапка таблицы, подблок, строка при наведении |
| Граница-разделитель | `border-border` | рамки блоков, разделители строк |
| Граница поля | `border-input` | только внутри примитивов полей |
| Основной текст | `text-foreground` | заголовки, содержимое |
| Приглушённый текст | `text-muted-foreground` | подписи, пояснения, пустые состояния |
| Второстепенный текст | `text-subtle-foreground` | даты, «необязательно» |
| Действие и ссылка | `bg-primary`, `text-primary`, `text-primary-foreground` | главная кнопка, ссылки, выбранный пункт меню |
| Мягкая подложка акцента | `bg-primary-soft` | выбранная строка, подсказка действия |
| Статусы | `success` / `warning` / `danger` (+ `-soft`, `-border`, `-foreground`) | `Alert`, `Badge`, ошибки полей |
| Выделение | `selected`, `selected-soft`, `selected-foreground` | выбранный день, выбранная ячейка журнала |

Тёмная тема — те же имена, другие значения (`[data-theme='dark']` на `<html>`). Экран о ней не знает.

**Цвет предмета приходит из базы и остаётся частью дизайна**: он применяется как метка и заливка
плитки. Это данные, а не оформление.

## Каркас страницы

```tsx
<Page>
  <PageHeader title="…" description="одна строка: зачем страница" actions={<Button>…</Button>} />
  <Stack gap="block">…блоки…</Stack>
</Page>
```

| Объект | Когда |
|---|---|
| `Page` | всегда, один на экран |
| `PageHeader` | заголовок страницы; `h1` — единственный на экран |
| `Stack gap="block"` | между блоками страницы |
| `Stack gap="field"` | между полями формы |
| `Stack gap="inline"` | внутри одного элемента: метка и значение |

Заголовки: `h1` — страница, `h2` — блок, `h3` — подблок. Уровень соответствует вложенности.

## Блоки

| Объект | Когда |
|---|---|
| `Card` | блок с заголовком и действием в шапке (`actions`) |
| `Section` | блок внутри страницы с заголовком и описанием |
| `Spoiler` | длинная страница из нескольких разделов: сводка + раскрытие |
| `Toolbar` | строка фильтров над списком |

**Правило вложенности:** не больше **двух рамок** по пути к содержимому. Спойлер — контейнер, а не
рамка. Блок внутри блока — один раз (панель внутри карточки), дальше только группы без рамки.

## Кнопки и ссылки

| Объект | Когда |
|---|---|
| `Button` (`primary`) | главное действие блока или формы — **одно** на блок |
| `Button tone="secondary"` | второе действие: «Отмена», «Сбросить» |
| `Button tone="danger"` | удаление и отчисление |
| `Button tone="ghost"` | действия в строке таблицы: «Править», «Удалить» |
| `Button size="sm"` | только в строках таблиц |
| `Link` | строчная ссылка в тексте |
| `Segmented` | выбор одного из нескольких видов («день / неделя») |

Навигация — **не кнопка**: выбранный пункт подсвечивается `bg-primary`, а не чёрной плашкой.

## Поля формы

| Объект | Когда |
|---|---|
| `Field` | всегда вокруг поля: подпись, подсказка, ошибка |
| `TextInput` | одна строка |
| `Select` | выбор из списка |
| `Textarea` | много строк |
| `Checkbox` | флажок: подпись **внутри** примитива |
| `FilePicker` | выбор файла |

Поля занимают всю ширину по умолчанию; ограничение — классом на конкретном поле (`sm:max-w-xs`).
Высота, рамка и радиус — забота примитива, в разметке их нет.

## Действия формы

```tsx
<FormActions submitLabel="Создать группу" pending={create.isPending} onCancel={onDone} />
```

«Отмена» — часть примитива: форма, открытая кнопкой, обязана закрываться.

## Создание записи

| Тип | Как |
|---|---|
| **В разделе** | кнопка в `actions` блока-списка; по нажатию форма **над списком**; после создания закрывается |
| **Внутри объекта** | в панели объекта: «Добавить период» в карточке года, «Зачислить» в составе группы |
| **Отдельной постоянной карточки нет** | форма, висящая на странице всегда, отодвигает список |

Пока форма открыта, кнопка в шапке **скрывается**: две одинаковые кнопки на экране путают.

## Правка записи в таблице

**Правило правки:** форма открывается **строкой в таблице под правимой записью**, на всю ширину
(`<tr data-static><td colSpan={…}>`), а не блоком под таблицей.

Причина: правя третью строку, человек смотрел вниз таблицы и терял, что именно правит. В строке
видно и запись, и её поля рядом.

Состояние полей живёт **в компоненте формы** этого элемента, а не в карточке: так не нужно очищать
пять состояний при переходе на другую строку. Пример — `SubjectEditForm` в `CatalogsScreen`.

## Выравнивание: способ, зафиксированный на будущее

Три правила, которые дают ровные формы без подгонки «на глаз».

**1. Поля — в сетке, а не в `flex flex-wrap`.**

```tsx
<div className="grid gap-3 sm:grid-cols-4">…поля…</div>
<FormActions submitLabel="Сохранить" onCancel={onDone} align="end" className="mt-3" />
```

Сетка даёт одинаковые колонки: поля не «каждое своей ширины». `flex` с полями разной ширины и
подсказками разной длины выравнивается по низу и разъезжается.

**2. Действия формы — справа и одной строкой (`FormActions align="end"`).**

Главное действие ищут справа, там же, где кнопку «Далее» в диалогах. Отдельная строка с «Отменой»
под полями читалась как второе действие, а не как пара «сделать / передумать».

**3. Подсказка под полем — по центру, если поле является группой элементов.**

`Field hintAlign="center"` для полей вроде даты со стрелками: подсказка слева от группы выглядит
оторванной от того, что поясняет.

### Почему это в примитивах, а не в разметке экранов

Свойства `hintAlign` и `align` живут в `Field` и `FormActions`: экран выбирает **намерение**
(«по центру», «справа»), а не пиксели. Иначе каждый новый экран повторял бы разметку и снова
разъезжался.

## Компактно или развёрнуто

Настройка в профиле («Оформление» → «Вид страниц»), личная, хранится на сервере.

| Вид | Как выглядит |
|---|---|
| **Компактно** (по умолчанию) | блоки свёрнуты в спойлеры: заголовок и краткое описание, содержимое по нажатию |
| **Развёрнуто** | блоки идут подряд: заголовок, пояснение, содержимое; сводок и «Развернуть» нет |

Действует на **все страницы со спойлерами**: «Справочники», «Настройки», «Настройки обучения».

**Решает примитив, а не страница.** `Spoiler` сам смотрит вид из сессии и выбирает разметку.
Страница про настройку не знает — иначе каждый экран делал бы это по-своему, и вид разъезжался бы
между разделами.

**Почему по умолчанию «компактно»:** это прежнее поведение. Обратный выбор по умолчанию внезапно
удлинил бы страницы у всех существующих учётных записей.

## Ряд фильтров

Ряд полей над списком выравнивается **по верхнему краю** (`items-start`), а не по нижнему.

Причина: подсказки под полями есть не у всех. При выравнивании по нижнему краю поле с подсказкой
сдвигает соседей без неё — кнопки уезжают вниз относительно полей. По верхнему краю сначала
выравниваются подписи (они у всех в одну строку), поэтому и поля встают на одну высоту, а подсказки
просто висят ниже.

Второе следствие: **в одном ряду лучше не смешивать поля с подсказками и без**. Если подсказка нужна,
она либо у всех полей ряда, либо выносится одной строкой под ряд.

## Данные

| Объект | Когда |
|---|---|
| `Table` | табличные данные: шапка, строки, наведение |
| `EmptyState` | данных нет: одно предложение, что сделать |
| `QueryState` | загрузка и ошибка запроса |
| `Pagination` | длинный список |
| `Alert` | сообщение о результате или ошибке |
| `Badge` | короткий статус в строке: «показана», «ожидание» |

## Проверки

| Команда | Что делает |
|---|---|
| `npm run check:ui` | запрещает палитру, сырые контролы и `gap-0/2/4/5` в экранах |
| `npm run ui:inventory` | пересобирает `docs/UI-INVENTORY.md`: сколько чего в разметке |
| `CAPTURE_SCREENS=1 npm run e2e:isolated` | снимки экранов в обеих темах для просмотра |

Снимки — **для человека**, а не эталон: локально Windows, в CI Linux, шрифты рисуются по-разному, и
сравнение с эталоном было бы вечно красным. Структурные нарушения ловит `check:ui`.

## Если нужно отступить от правил

Отступление допустимо, если **смысл другой** (например, второй акцент для семантики, а не «так
красивее»). Тогда:

1. добавьте **роль** в `index.css` (светлое и тёмное значение — проверка наборов токенов не даст
   забыть второе);
2. запишите решение в [`UI-DECISIONS.md`](./UI-DECISIONS.md);
3. если правило мешает — меняйте **правило** в `tools/quality/ui-rules.mjs`, а не обходите его
   классом в разметке.
