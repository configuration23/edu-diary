# PHASE-3-FIXES — правки по замечаниям к Этапу 3

Журнал мелких правок владельца по итогам просмотра релиза Этапа 3 (расписание и уроки)
на тестовом стенде.

Правило работы: один блок — один заход с тестами и одним коммитом; перед правкой блока
решение из «Открытых вопросов» согласуется. Схема БД для этих правок не меняется, кроме
возможного нового серверного маршрута в блоке 2.

**Состояние: правки не начаты.** Ничего из перечисленного в коде пока не тронуто —
раздел заполнен как список к работе.

## Блок 1. Начало назначения — по умолчанию начало учебного года

- [ ] В форме «Новое назначение» поле «Начало» предзаполнять датой начала активного
      учебного года, оставляя поле полностью редактируемым.
- Место: `apps/web/src/screens/AssignmentsScreen.tsx` (поле «Начало», сейчас
  `useState('')` — пустое).
- **Замечание.** Начало года сейчас недоступно клиенту: `AcademicContext` отдаёт только
  `activeYearTitle`, а сам год (`startsOn`/`endsOn`) запрашивается внутри контекста и
  наружу не выходит (`apps/web/src/components/AcademicContext.tsx`). Нужно добавить в
  контекст `activeYearStartsOn` — он же понадобится блоку 3.
- Подстановку делать начальным значением состояния, а не `value={startsOn || yearStart}`:
  иначе в `<input type="date">` пользователь увидит пустое поле. Если активного года нет —
  поле остаётся пустым, как сейчас.

## Блок 2. В назначениях группа «Все»

- [ ] В списке групп формы «Новое назначение» добавить вариант «Все группы»: выбранный
      преподаватель получает назначение по этому предмету и в эти сроки в каждой
      существующей группе.
- Место: `apps/web/src/screens/AssignmentsScreen.tsx`; сервер —
  `apps/api/src/modules/staffing/staffing.service.ts` (`create` принимает **одну**
  `studyGroupId`).
- **Открытый вопрос (решение владельца).** Два варианта:
  1. клиент делает N последовательных `POST /api/assignments` — просто, но не атомарно:
     часть групп создастся, часть вернёт `409`;
  2. серверная операция на список групп — один запрос, отчёт «создано / конфликты по
     группам», один контекст аудита; это правка API, контрактов и тестов.
- **Замечание.** Правило «предмет в группе ведёт один преподаватель» остаётся, поэтому
  режим «Все» может частично не пройти. Интерфейсу нужно показать, в каких группах
  назначение не создалось и почему (`details.reason = subject_overlap`).

## Блок 3. «Действует с» в «Добавить занятие» — по умолчанию начало учебного года

- [ ] В блоке «Добавить занятие» раздела «Расписание» поле «Действует с» предзаполнять
      датой начала активного учебного года, оставляя поле редактируемым.
- Место: `apps/web/src/screens/ScheduleScreen.tsx` — сейчас передаётся сегодняшняя дата
  (`yearStart={new Date().toISOString().slice(0, 10)}`).
- Зависит от той же доработки `AcademicContext`, что и блок 1.

## Блок 4. «Пользователи и роли» → «Учётные записи и роли»

- [ ] Переименовать раздел и заменить «Пользователи» на «Учётные записи» в его текстах.
- Места:
  - навигация — `apps/web/src/components/AppLayout.tsx` (`label: 'Пользователи и роли'`);
  - сам раздел — `apps/web/src/screens/UsersScreen.tsx`: «Пользователи» (заголовок
    таблицы), «Новый пользователь», «Создать пользователя», «Пользователей нет»,
    «Пользователь создан…», «Пользователь получит расширенные права», «Роли пользователя»,
    «сессии пользователя отозваны»;
  - перекрёстные ссылки на раздел — `AssignmentsScreen.tsx`, `StudentsCard.tsx`
    (два текста пустого состояния), `PrivacyScreen.tsx` (комментарий), комментарий в
    `apps/web/src/lib/queries.ts`.
- **Замечание.** Ломаются сквозные проверки: `e2e/phase-1-flow.spec.ts` ищет ссылку
  «Пользователи и роли» (и отдельно проверяет, что преподавателю её не видно),
  заголовок «Новый пользователь» и текст «Пользователь создан». Их нужно поправить тем же
  коммитом, иначе e2e покраснеет. Термин «роль» при этом не меняется.

## Блок 5. В «Расписании» блок «Добавить занятие» — первым

- [ ] Переставить карточку «Добавить занятие» выше карточки со списком занятий.
- Место: `apps/web/src/screens/ScheduleScreen.tsx` (карточка сейчас после таблицы).
- **Замечание.** Блок показывается только при `editable && selectedGroupId !== null`, то
  есть у администратора при открытии раздела (группа = «Все доступные») его не видно.
  Порядок имеет смысл только когда блок отображается; отдельно решаем, не нужно ли
  подсказать выбрать группу.

## Блок 6. Название аудитории — серым текстом в выборе

- [ ] В списках выбора аудитории показывать её название, а не только номер, серым текстом.
- Места: `apps/web/src/screens/ScheduleScreen.tsx` (форма «Добавить занятие» и правка
  занятия), `apps/web/src/screens/LessonsScreen.tsx` (правка урока); в таблице расписания
  тоже выводится только `room.name`.
- **Замечание.** В `<option>` браузер не даёт стилизовать часть текста, поэтому «серым»
  можно сделать только подпись под селектом (выбранная аудитория) либо строку целиком в
  списке. Имя аудитории — это `room.name` («ДЕМО-кабинет 101»), а необязательное описание
  лежит в `room.note` (справочник аудиторий в `CatalogsScreen.tsx`).
- **Открытый вопрос (решение владельца).** Что показывать: примечание в списке одной
  строкой или подпись с названием выбранной аудитории под селектом.

## Порядок работы

1. **Клиентский заход**: блоки 1, 3, 4, 5, 6 — общая доработка `AcademicContext`
   (`activeYearStartsOn`), тексты, порядок блоков, подписи аудиторий; правка e2e по
   переименованию.
2. **Серверный заход**: блок 2 — после решения по варианту (атомарная серверная операция
   или последовательные запросы с отчётом).

Блоки 1 и 3 не зависят от остальных; блок 4 обязательно идёт вместе с правкой e2e.
