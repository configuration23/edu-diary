# Версионирование

Коротко: одна версия на весь монорепозиторий, `MINOR` растёт вместе с закрытым
этапом роадмапа. Версия схемы базы отдельная — её показывает число применённых
миграций.

## Правило

| Часть версии | Когда растёт | Пример |
|---|---|---|
| `MAJOR` | выход на реальных людей, когда систему можно вести в боевом режиме | `1.0.0` — после Этапа 7 |
| `MINOR` | этап роадмапа закрыт и принят | Этап 3 → `0.3.0`, Этап 4 → `0.4.0` |
| `PATCH` | правки и исправления внутри этапа, приёмку не меняют | `0.2.1` — исправление после сдачи |

Сейчас версия всех пакетов — `0.4.0`: последним закрытым и принятым остаётся Этап 4 (журнал).
Этапы 5 («домашние задания») и 6 («компоновка интерфейса») сделаны, но версию пока не двигали:
рост до `0.5.0` и `0.6.0` — при приёмке владельцем. Работы по ИБ версию не меняют: это
исправления и усиление внутри этапа (`PATCH`), их итог фиксируется при слиянии ветки
`security/hardening`. Версии всех пакетов сверяет `npm run check:version` (шаг в CI).

## Три версии, которые видит администратор

На экране «Обзор» в блоке «О версии» показаны:

1. **Версия API** — из `GET /api/health` (`version` в ответе).
2. **Версия интерфейса** — вшивается в бандл при сборке (`vite.config.ts` читает
   корневой `package.json`, значение доступно как `__APP_VERSION__`).
3. **Схема БД** — число применённых миграций из того же ответа.

Зачем две версии приложения: интерфейс и API собираются отдельно, поэтому в
браузере может остаться старая сборка. Если версии разошлись, экран показывает
предупреждение «обновите страницу с очисткой кеша» — это заменяет догадки о том,
«почему не видно новых кнопок».

## Как поднять версию

Версии всех пакетов должны совпадать: их сверяет проверка `check:version`
(входит в локальные шлюзы и в CI).

```bash
# 1. Правим version в корневом package.json (единственное место).
# 2. Разносим по пакетам:
node tools/quality/sync-version.mjs --write
# 3. Проверяем (это же делает CI):
npm run check:version
```

Версию схемы базы поднимать не нужно: она следует за миграциями и видна по их
числу. Новый файл миграции — это уже изменение схемы, отдельного поля нет.

## Что не версионируется этим правилом

- **Редакции политики обработки ПДн** — у них свои версии (`policy.version`),
  не связанные с версией приложения.
- **Справочники** (предметы, категории, аудитории) — данные, а не код.
