# PHASE-7-PLAN — Этап 7. Эксплуатация (не начат)

| Поле | Значение |
|---|---|
| Этап | 7 |
| Состояние | **не начат** — план этапа составляется перед работой |
| Слияние | — |
| Версия | `1.0.0` после этапа (`VERSIONING.md`) |
| Отложенное | см. `BACKLOG.md`, раздел 6 |

Этап-условие: **до допуска реальных людей он обязателен**. Редизайн (этап 6) его не отменяет: без
проверенного восстановления из бэкапа реальные данные ставить рискованно.

Основание: `ROADMAP.md` §Этап 7, `ARCHITECTURE.md` §12, `SECURITY.md` §3.6 и §8.

## Что должно войти

| Блок | Состав |
|---|---|
| **Резервные копии** | `pg_dump -Fc` по расписанию, шифрование, хранение вне сервера приложения, **проверенное восстановление** в отдельную базу (не «сделали дамп — на этом всё») |
| **Установка на чистой машине** | пошаговая инструкция, `bootstrap:env`, миграции, первый запуск, проверка после установки |
| **Обновления и откат** | порядок выкладки, что делать при неудачной миграции, как откатиться на предыдущий образ |
| **Наблюдаемость** | структурированные логи с ротацией, `/api/health` и `/api/ready`, наблюдаемость бизнес-событий, алерты по ошибкам `5xx` |
| **Сроки хранения** | `retention:purge` — что и когда удаляется, акт уничтожения (`SECURITY.md` §3.6) |
| **Реагирование на инциденты** | порядок действий, ответственный, уведомления (`SECURITY.md` §7) |
| **Перенос данных** | выгрузка и загрузка из админского интерфейса — состав и правила безопасности (четыре открытых вопроса в `ROADMAP.md`) |

## Критерии приёмки

1. Восстановление из бэкапа **проверено руками** на отдельной машине: система поднимается, вход
   работает, данные на месте.
2. Установка на чистой машине проходит по инструкции без правок «по ходу».
3. Инструкция по обновлению и откату проверена на стенде.
4. Алерты хотя бы по `5xx` и недоступности БД.
